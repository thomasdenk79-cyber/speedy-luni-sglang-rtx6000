# FlashInfer / sglang-kernel upgrade audit (NVFP4 Cake QSA decode)

**Verdict: STAY on flashinfer-python 0.6.17 + custom sglang-kernel 0.4.6.post1+cu130 + torch 2.13.0+cu130 for the running stack. Do not upgrade in place.** Upgrade only as a separate, isolated rebuild after the frozen overlay rebase is finished.

Read-only audit on 2026-11-25. No venv, no install into shared state, no GPU use. Only `pip download --no-deps` into `/tmp/opencode/fi-audit/wheels`; wheel `py3-none-any`, 124.3 MB. Port 8001 untouched.

## 1. Does 0.7.5.post1 ship Cake QSA sources? — No (partially)

`flashinfer_python-0.7.5.post1-py3-none-any.whl` RECORD contains exactly **5** paths under `flashinfer/experimental/cake_qsa_nvfp4/`:

`__init__.py`, `build.json`, `cake_backend.py`, `cake_build.py`, `cake_jit.py`.

- **No `csrc/*.cu`** and **no `aot/*.so`** — none of the 7 overlay kernel hash stems (`4f13e4710a…`, `6692f812…`, `aa2349948…`, `b56eb690…`, `dfd8600d…`, `ecb46ae2…`, `f0ae7070…`) appear anywhere in RECORD.
- `build.json` declares 22 libraries with `sources: csrc/...cu` and `path: aot/...so`, `min_cuda: 12.8`, generated by `cake_revision af753f66…` / CUDA 13.4.92 (2026-10-27). `cake_build.py::_verified_sources()` fails closed when those files are missing.
- The sources exist only in upstream checkouts: `/tmp/opencode/flashinfer-v074/flashinfer/experimental/cake_qsa_nvfp4/csrc/` and `/tmp/opencode/flashinfer-upstream/.../csrc/`.
- The 5 Python/manifest files of our overlay at `/tmp/opencode/cake-qsa-sm120/cake_qsa_nvfp4/` are **byte-identical** to 0.7.5's payload (base64url sha256 from RECORD matches for all 5). Only `csrc/` and `aot/` are additive.
- Our `aot/` has 4 prebuilt `sm_120a` `.so` (target GPU); the other 18 (arch) libraries must JIT from `csrc/`.

**Implication:** upgrading removes the need to backport the Python API/JIT driver, but **does not remove the need for our overlay** — `csrc/` (and preferably the 4 `sm_120a` `.so`) must still be copied into the installed package.

Additional upside of 0.7.5: `flashinfer/sparse.py` and `flashinfer/qsa.py` now exist and `sparse.py` defines `qsa_sparse_paged_attention`. Installed 0.6.17 has neither `qsa.py` nor that symbol, so 0.6.17 requires the current patch/overlay wiring for the public entry point.

## 3. sglang-kernel 0.4.11 would regress the workload

File-list diff, installed custom `0.4.6.post1+cu130` vs upstream wheel `0.4.11`:

- `0.4.11` drops 59 paths: `sgl_kernel/flash_attn.py`, `flash_mla.py`, `sparse_flash_attn.py`, `spatial.py`, their `.so`s, **and the whole `triton_kernels/` tree including `triton_kernels/specialize.py` (spec-decode kernels)**.
- `sglang/speculative.py` is byte-identical in both — 0.4.11 adds no new spec-decode kernel. This confirms the earlier note: 0.4.11 lacks our spec-decode coverage.
- 0.4.11's only additions are the wheel metadata and `infllm_ops.cpython-311-...so`.

Do not replace the custom `+cu130` sglang-kernel build.

## 4. Why the earlier 0.7.5 rebase stalled (`/tmp/opencode/fi-rebase`)

It is a scratch 3-way merge workspace, not a repo: two variants `vt/` and `vtoea/` (the sglang overlay flavors), each holding `.base` (custom 0.6.17 overlay), `.new` (upstream 0.7.x) and `.merged` files for 7 files (`jit/core.py`, `jit/fused_moe.py`, `fused_moe/core.py`, `gdn_decode...py`, 3 fused-MoE CUTLASS kernel files).

- `gdn_decode_bf16_wy_output_only.py` and `jit/core.py` merged cleanly (base→merged == base→new plus a "Modified by aiueo52 for flash-next-fast" notice).
- **Unresolved conflicts remain** in `fused_moe/core.py.merged` (9 conflict hunks: `tactic_rows_policy`, new `da_moe`/`NVFP4_4over6` imports, fused-MoE paths), `jit/fused_moe.py.merged`, `cutlass_fused_moe_kernels.cuh.merged` and `flashinfer_cutlass_fused_moe_binding.cu.merged` — in both variants. No conflict was resolved, no build/test followed.
- Blocker for a real upgrade: `tools/assemble_flashinfer.py` hard-codes `VERSION = "0.6.17"` and validates all wheel/overlay hashes from `flashinfer-overlays/MANIFEST.json` (15 source overlays). Bumping FlashInfer means regenerating that manifest and re-porting all custom MoE/GDN patches upstream of 0.7.5 — the work that stalled here.

## 5. Recommendation

1. **Stay** for port 8001 and the current benchmark campaign. The only concrete gain from 0.7.5 (native Cake QSA Python API) does not eliminate the overlay, while it forces a cutlass-dsl/cudnn frontend bump and a full, unfinished overlay rebase.
2. **Never** adopt `sglang-kernel==0.4.11` with torch 2.15; 0.4.11 pins torch 2.14.1 and drops spec-decode/flash-attn/flash-mla modules. Keep the custom 0.4.6.post1+cu130 build and torch 2.13.0+cu130.
3. If upstream fixes are needed later, do an isolated build (below) and keep it separate from the serving venv until parity tests pass.

## 6. Exact isolated-build steps (only if upgrading)

```bash
SCRATCH=/tmp/opencode/fi-audit
python3.12 -m venv $SCRATCH/venv-fi075          # or: uv venv --python 3.12 $SCRATCH/venv-fi075
V=$SCRATCH/venv-fi075/bin
$V/python -m pip install -U pip
# keep torch at the known-good pair, do NOT install 0.4.11 / 2.14.1 / 2.15
$V/python -m pip install 'torch==2.13.0+cu130'   # use the same local wheel/index as the serving venv
$V/python -m pip install 'flashinfer-python[cu13]==0.7.5.post1'
PKG=$($V/python -c 'import flashinfer,os;print(os.path.dirname(flashinfer.__file__))')/experimental/cake_qsa_nvfp4
# 0.7.5 already ships the 5 Python/build.json files byte-identical to our overlay; add only payload:
cp -a /tmp/opencode/flashinfer-v074/flashinfer/experimental/cake_qsa_nvfp4/csrc $PKG/
cp -a /tmp/opencode/cake-qsa-sm120/cake_qsa_nvfp4/aot $PKG/
$V/python - <<'PY'
from flashinfer.experimental import cake_qsa_nvfp4 as c
from flashinfer.experimental.cake_qsa_nvfp4 import cake_build
print(c.qsa_sparse_paged_attention, len(cake_build.jit_specs('sm_120a')))
from flashinfer.sparse import qsa_sparse_paged_attention  # new in 0.7.x
PY
```

- `csrc` digests are verified by `cake_build._verified_sources()`; use the exact upstream `csrc/`, not hand-edited copies. Rebuild `aot/` (`cake_build.py` builder path) only if the prebuilt sm_120a `.so` is rejected by the new tvm-ffi/cutlass-dsl.
- **Before switching serving**: finish the `fi-rebase` ports — resolve the 9 `fused_moe/core.py` conflicts + `jit/fused_moe.py` + both CUTLASS kernel files for `vt` and `vtoea`; set `assemble_flashinfer.py VERSION` to `0.7.5.post1`; regenerate `flashinfer-overlays/MANIFEST.json`; rebuild both overlay trees; run the GDN / fused-MoE / NVFP4 QSA suites on a GPU with the port-8001 job stopped.
- Keep `sglang-kernel` and `torch` unchanged in the serving venv; validate the isolated venv's import/ABI parity (`sgl_kernel` import, c10::cuda symbol check) before any promotion.
