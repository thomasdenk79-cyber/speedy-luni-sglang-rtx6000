## The three campaign arms

Branch-level facts plus what the commits actually are, so a reviewer can see whether a
missing number in rc2 is a missing patch or a missing test.

**`perf/hb-lowrow-kernels` (10/10, QFN-0193..0202, 2026-11-18)** — HyperBurst low-row GEMV
kernels: draft MoE W4A16 GEMV port, MoE router gate as Triton GEMV at 1..16 rows, MTP entry
`fc` on the sm_120 skinny GEMV, MXFP8 fused-norm GEMV fold into `out_proj`, plus five
correctness guards (wrong-rank activations, wrong-layer activations, sm_120-only routing,
row-contiguous weight gate, bounded routes / no grad inputs).

**`perf/hb-prune-pdl` (20/20, QFN-0203..0214, 2026-11-18/19)** — singleton-route pruning and
Triton PDL (programmatic dependent launch): registers `SGLANG_TRITON_PDL` and the canonical
prune tau, gates PDL wait/trigger on it, ranks only live routes when picking the top-1 seat,
pins reused histogram scratch to zero, probes the platform without publishing a poisoned
snapshot; the other 8 commits are CPU unit tests and register docs.

**`feat/draft-vocab-head-buckets` (23/23, QFN-0170..0192, 2026-11-18)** — draft-head vocab
size buckets: bucket ladder on the worker, batch-size-rounded head buckets, LRU-ordered draft
head, capture against the batch's head bucket, eager-extend binds to the padded graph shape,
recency carried over restarts, plus spec/test/docs commits. This is the branch the
"vocab-buckets" arm runs.

## Hygiene defects found while measuring

Reported, not fixed — none of these belong to this task and all of them are cheap to fix later.

1. **Worktree names do not describe content.** `sglang-wt-rc3` is checked out at
   `rc/qwen38-rc4`; `sglang-wt-tagrc2` and `/tmp/rc2-prepatch` sit detached at
   `1ad4f14e1` (QFN-0154). Only `git worktree list` + `rev-parse` are trustworthy; the earlier
   campaign docs that cite a worktree name as provenance are wrong.
2. **Shared trees carry foreign WIP.** `qwen38-flashnext-nvfp4-kv` has uncommitted changes in
   `examples/run-upstream.sh`, `gpuq-runner.py`, `gpuq_prod.py`, `server_args.py`,
   `qwen4_exp.py`, `restore-kv.py` and untracked `-` and `.aider.chat.history.md`. Any arm
   built from a shared tree would silently measure someone else's edit. Build arms only from a
   dedicated worktree pinned to a SHA — that is why
   `/srv/community-repos/sglang-wt-speedybase` exists.
3. **Test debris in the queue repo.** `scripts/gpu-queue/` contains directories named
   `<pytest_fixture(<function root at 0x…>)>/queue` — a test ran against an unresolved root. Harmless,
   but it makes `git status` dirty in a repo that arms are built from.

## How to re-measure

```bash
G=/srv/community-repos/sglang-upstream
env -u GIT_INDEX_FILE git -C $G merge-base rc/qwen38-rc2 upstream/main
env -u GIT_INDEX_FILE git -C $G rev-list --left-right --count rc/qwen38-rc2...upstream/main
for b in perf/hb-lowrow-kernels perf/hb-prune-pdl feat/draft-vocab-head-buckets; do
  echo "$b ahead=$(env -u GIT_INDEX_FILE git -C $G rev-list --count rc/qwen38-rc2..$b) \
plus=$(env -u GIT_INDEX_FILE git -C $G cherry rc/qwen38-rc2 $b | grep -c '^+')"
done
# register totals, parsed (never grep -c over a markdown table: labels repeat in prose)
python3 - /srv/community-repos/qwen38-flashnext-nvfp4-kv/docs/PATCHES.md <<'PY'
import re,sys
from collections import Counter
c=Counter()
for l in open(sys.argv[1],encoding='utf-8'):
    m=re.match(r'\|\s*(QFN-\d{4})\s*\|\s*([^|]+)\|',l)
    if m: c[m.group(2).strip()]+=1
print(sum(c.values()),dict(c))
PY
```

`env -u GIT_INDEX_FILE` is mandatory for every git call here: the operator exports a private
index and an inherited `GIT_INDEX_FILE` corrupts the shared repo's index (live hit, task 77).
